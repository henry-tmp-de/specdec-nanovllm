## 0. 摘要（先看这五条）

1. **纯滑窗的 M 轴几乎没有拐点。** M 从 3 加到 24（draft 池 12→96 块，8 倍），

3. **★★ 关键答案（本轮最值钱的一个数）：**
   > 本轮同一批次里，普通投机（`window=0`，draft 池 **173** 块）的接受率是 **0.6911（B=1）/ 0.6815（B=4）**。

   > TTFT 99 ms（M=33 要 328 ms）。**
   > ★ **没有任何配置达到 α ≥ 0.75** —— 因为本轮**普通投机自己**就只有 0.691，
   > 0.75 那个门槛来自上一轮**并行跑**时测到的 0.781（上一轮自己的串行值也是 0.6911）。
4. **P 的最优值不稳定，但"P=1 就够用"很稳。** P=0→1 是**大幅、系统性**的一跳；而 **P≥1 之后

## 1. 出发点：draft 的上下文里，开头那几个块被整个丢掉了

`_run_draft_prefill_window`（旧版）取的是 `[b0*bs, end)`，其中
`b0 = max(valid_from//bs, (end-1)//bs − M + 1, 0)` —— **只留最近 M 块，序列最前面
的块全丢**。RoPE 用的是绝对位置，所以丢的是**开头那段内容**，不是位置编号。

序列开头那几个块对整串序列有**定位作用**（"attention sink"那一类），小窗口下丢了它们
接受率会掉。台账里 **P7-D 挂的动机正是"小窗口下接受率掉"**。本轮把它做了出来并量化。

**改动前先算了一笔容量账**（判据：`(P+M) × max_num_seqs < 普通投机池块数`）：

| 配置 | draft 池 = (P+M)×4 | target 池（实测） | vs 普通投机 173 |
|---|---:|---:|---:|
| M=5 独用 (P=0) | 20 | **293** | +69% |
| P=2, M=5 | 28 | **287** | **+66%（只少 6 块，−2%）** |
| P=4, M=5 | 36 | **280** | +62% |
| P=1, M=12 | 52 | **268** | +55% |

⇒ **P 轴很便宜**，值得实测。

## 2. 实现（★ 默认行为一字未变、可关、老路径一行没删）

### 2.1 核心设计：一块数组，两段职责

`draft_block_table` 从「M 个环块」变成「**P 个常驻块 + M 个环块**」（共 P+M 项）：

```
slot(p) = ring[b] * bs + p%bs                     当 b = p//bs <  P   ← 开头常驻
        = ring[P + (b−P) % M] * bs + p%bs         当 b        >= P   ← 最近窗口的环
b0(pos) = max(P, valid_from//bs, pos//bs − M + 1)                 ← 恒 ≥ P
ctx_len = P*bs + (pos + 1 − b0*bs)
block_table = ring[0:P] + [ ring[P + ((b0+t)−P) % M] for t in range(M) ]
```

- **P=0 时逐值退化成旧公式**（`slot = ring[b%M]*bs+p%bs`、`b0 = max(0, …)`、
  `bt = [ring[(b0+t)%M] …]`）—— 有 CPU 测试逐值对着老的内联公式比（§3.1）。
- ★ **两段永不重叠**：`b0 ≥ P` 恒成立 ⇒ 序列短到"窗口已经够到开头"时，b0 被夹在 P，
  两段**首尾相接**（`b0==P` ⇒ 可见集 = `[0, end)` 连续），绝不会把同一个块放两次。
- ★ **块表恒按绝对块号递增**：前 P 项是绝对块 `0..P−1`，后 M 项是 `b0..b0+M−1`，
  且 `b0 ≥ P` ⇒ 拼接后严格递增、无重复（CPU 测试逐格验）。

### 2.2 draft prefill：两段拼成一个 local-causal chunk

`_run_draft_prefill_window` 把 `[0, head_end)` 与 `[b0*bs, end)` 两段**按绝对位置递增
顺序拼成一个 chunk**（中间空档跳过），走**本地 k/v + 因果**那条路（不传 block_table）：

- chunk 内的 causal 掩码 = layout 下标比较 ⇒ 尾部 query 看到"开头 + 它之前的尾部"，
  开头 query 只看到更早的开头 —— **恰好是我们要的可见集**；
- RoPE 用**绝对位置**（`positions` 两段分别 `range(0,head_end)` / `range(b0*bs,end)`）；
- 写槽仍走 `slot(p)` 落进常驻块 / 环块。

### 2.3 解码：块表两段拼接，paged 内核读回来

`DraftWindow.block_table()` 返回 `P+M` 项，`ctx_len` 用它截断。
解码是**单 query**，flash-attn 只读 `ceil(ctx_len/bs) = P + ⌈(end−b0*bs)/bs⌉` 项，
多出来的项不会被读；**顺序不影响单 query 的 softmax**，但我们仍保持递增把它当不变量守着。
draft CUDA 图的块表宽度 = `ceil(16640/256) = 65` 列 ≥ P+M（最大 41）⇒ **不退回 eager**。

   所以这一层的差异**不能当成系统效应读**。
   ⇒ 诚实结论：**"常驻 1–2 个块就拿到几乎全部收益"**；再说"P 有最优值/越大越好/越大越坏"都超出数据。
3. **全网格 25 格没有一格达到 α ≥ 0.75** —— 见 §4.3。

### 4.3 ★★ 「要求 α ≥ 0.75，draft 池最小能压到多少块？」的明确回答

**答：本轮 25 格没有任何配置达到 α ≥ 0.75。** 原因是**分母问题**：
本轮**同一批次**测得普通投机（window=0，draft 池 173）的接受率只有 **0.6911（B=1）/ 0.6815（B=4）**；
**0.75 这个门槛来自上一轮并行跑时测到的 0.7814**（上一轮自己串行重跑也是 0.6911，与本轮一致）。
⇒ **α ≥ 0.75 在本轮条件下连普通投机都达不到，不是 P7-D 的失败。**

**把门槛改成"追平同一批次的普通投机"（这才是可比的问法），答案是：**

> **B=1（门槛 = 0.6911）**：
> - **draft 池最小 = 24 块**（`P=1, M=5`，α=**0.6787**，低 1.8% —— 落在轨迹散布内）；
> - **28 块**（`P=2, M=5`，α=**0.7039**）则**稳定追平/略超**。
>
> **B=4（门槛 = 0.6815）**：
> - **draft 池最小 = 40 块**（`P=2, M=8`，α=**0.6964**，高 2.2%）；
> - 28 块（`P=2, M=5`，α=0.6709）低 1.6%，也在散布内。
>
> **★ 综合取 `(P=2, M=5)`：draft 池 28 块 = 普通投机 173 块的 16%（−84%），
> target 池 287 块（容量 +66%，44,288 → 73,472 token），
> TTFT 101.5 ms（普通投机 93.1；★ 而"不截断"的 M=33 要 331.9 ms，是本方案的 3.3 倍）。**

**Pareto 前沿（draft 池 → 最好 α，B=1）**：
`12→0.400` · `16→0.562` · `20→0.568` · `24→0.679` · **`28→0.704`** · `40→0.713` · `64→0.729` · `132→0.720` · `173→0.691`。
⇒ **28 块拿到 0.704；再往后多花 1.4~4.7 倍的块，只换来 +0.009 ~ +0.025 α**。
**角就在 (P=2, M=5)。**

## 6. 没做 / 测不出 / 挂账（★ 必读）

| 没包含 | 说明 |
|---|---|
| **"最优 P" 到底存不存在** | ★ **测不出**。P≥1 的 20 个格子 α 落在 0.5619–0.7286、峰的位置随 M 乱跳，而各格 `out_md5` 全不同（temp=1.0 发散）⇒ **这一层差异分不清"系统效应"还是"轨迹散布"**，本轮**不下结论**。要分清必须**同一轨迹**做消融（比如固定 draft 为 teacher-forcing），**没做**。 |
| **为什么 P=0→1 是系统性的一跳** | ★ **未隔离**。机制猜测是"开头段当 attention sink / 全局锚点"，但**没有任何机制级证据**（没做 attention 权重的可视化、没做"只留前 4 个 token vs 前 256 个"的对照）。 |
| **为什么 B=4 的每块成本是 B=1 的 ~11 倍** | ★ **未隔离**。`ms/轮(maxB) ≈ 57.5 + 1.11×(P+M)` 是**拟合出来的**，只做了 28 个格子的经验关系，**没有 profile 到具体环节**。 |
| **α ≥ 0.75 的门槛** | 本轮条件（`max_num_seqs=4`、串行、热缓存、自然长文）下**普通投机自己只有 0.691**，门槛不可达。**换负载/换口径**（上一轮并行、或更低温度的合成素材）能否到 0.75 未测。 |
| **ctx=4096 / 16384** | 本轮**只做了 ctx=8192**。4096 与 16384 的 P 轴未扫（上一轮已知 16K 下 M 也要跟着放大）。 |
| **k 的扫描** | 固定 k=6。P/M 与 k 的交互未测。 |
| **`(P,M)` 与真实并发的交互** | 只测了 B∈{1,4}；`max_num_seqs=4`。**P+M 变大时容量优势会缩**，但没扫并发上限。 |
| **冷启动 TTFT** | 全是热前缀缓存稳态（draft prefill 只跑窗口）；冷缓存下 target 也要跑整段 prompt，P7-D 的相对劣势会更小（**未测**）。 |
| **无损性（分布级）** | 本轮只做了"默认/纯滑窗逐字节等价"（§3.2）与 P7-D 的自洽（§3.3）。三档无损性证据在台账 §2.8/§2.9，**本轮不重复**。 |
| **低温度对照没能给出确定性判据** | 加跑 `TEMP=0.01` 的 `w0_full` 两树仍不同（`9ea29c2c` vs `f9100057`）—— 96 个 token 下任何一个 ULP 翻转都会发散，**这条对照无效**，改用"同树重复跑 3 遍"来证明抖动是环境噪声（§3.2）。 |
