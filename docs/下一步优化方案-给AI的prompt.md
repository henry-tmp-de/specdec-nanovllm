## 二、你要产出什么

一份 `docs/下一步优化方案.md`，包含：

### 1. 候选方向清单（表格）

每个候选方向一行，**必须包含这几列**：

| 列 | 要求 |
|---|---|
| 方向 | 一句话说清做什么 |
| **打哪个考点** | 对应 `面试考点分析.md` 里的哪个桶 + **该桶的考频** |
| **★ 那个桶里真正问这个的有几道** | **不许只写大类占比**（见下"思维陷阱"） |
| 别人做到哪了 | 引 `生态调研`，说明是否撞车、撞到什么程度 |
| 我们的基础 | 我们已经有什么可以复用 |
| 实现成本 | 高/中/低 + 大致人天 |
| **能产出什么数字** | **具体到指标名**（吞吐？TTFT？P99？显存？并发上限？） |
| 风险 | 最大的不确定性是什么 |

### 2. 排序 + 推荐

- 给出你推荐的优先级顺序，**并解释排序依据**（不要只说"综合考量"）
- 明确区分：**哪些是"必须先做的前置"**、**哪些能最快出数字**、**哪些是压轴大活**

### 3. 明确「不做什么」及理由

列出你**主动排除**的方向，每个给一句理由（比如"考频 0%、别人做透了、成本过高"）。

### 4. 每个推荐方向的验收标准

对排在前面的 2-3 个，写出**可验证的完成判据** ——
不是"优化了 attention"，而是"在 ctx=16k、batch=1 下，端到端吞吐从 X 提到 Y"。

## 三、硬性要求

### 3.1 ★ 不许用"大类占比"给具体技术背书

**这是本项目已经栽过两次的坑，你必须避开：**

- 曾经说「KV 量化命中**显存KV 6.1%**」→ 实际量化桶 8 道**全是权重/激活量化**，
  KV 量化**面经题 0 道**（只在 JD 里出现过）
- 曾经说「KV 生命周期命中**前缀缓存/调度 7.8%**」→ 实际那 14 道里 **10 道是调度**，
  前缀缓存只有 4 道，**「淘汰/LRU/写时复制」命中 0 道**

**所以：说一个方向"打中某考点"时，必须去 `面试考点-逐题分桶.md` 里数一遍
「这个大类里真正问这件事的有几道」，并把数字写出来。**

### 3.2 不许和已有的工作重复

`优化总览.md` 里已记录的都算做过（含 CUDA Graph、投机解码、Triton + CUDA 两版
paged decode attention、37 项测试）。**别把已经做完的再写进计划。**

### 3.3 不许和别人撞车

`生态调研` 里列的方向，如果已经有 ≥3 个独立实现，**默认不推荐**，
除非你能说清"我们比别人深在哪"。

### 3.4 成本要诚实

不要写"工作量中等"这种模糊话。给区间（如"3~5 人天"）并说明卡点在哪。
如果某个方向需要**多张 GPU**，必须写出来 —— 服务器是共享的 8×3090，
经常只有 1~2 张空着，且**不能抢别人的卡**。

### 3.5 不许编造

所有"别人做了什么"必须能在 `生态调研` 或你自己**实际打开**的链接里找到。
链接打不开就标注，别猜内容。

## 四、背景约束（决定方案长什么样）

1. **硬件**：8× RTX 3090（**sm_86, Ampere**），共享服务器，通常只有 1-2 张空卡。
   **TMA / TMEM / 2-SM cluster 在 sm_86 上物理不存在**，别推荐。
2. **ncu 用不了**：`RmProfilingAdminOnly: 1` 且账号无 sudo → 拿不到硬件计数器。
   `nsys` 和 `torch.profiler` 可用。**别推荐依赖 ncu 的方案。**
3. **网络不稳**：`ssh lab3090` 会随机掉线。长任务要 `setsid ... > 文件`，别直接管道。
4. **服务器工作副本不是 git 仓库**，本地 `D:\学习\specdec` 才是；改完 `scp` 推上去。
5. **nano-vllm 硬编码 `tcp://localhost:2333`，测试必须串行。**

## 五、给你的一条重要提示

`面试考点分析.md` 的结论是：**172 道题里前四桶占了 64.5%**
（模型结构 20.9% / 调度 12.2% / 分布式 11.0% / CUDA 10.5% / prefill-decode 9.9%），
而**我们已经命中最重的两块（CUDA 10.5% + prefill/decode 9.9%）**。

所以你要判断的一件事是：

> **「再找一个新考点来做」的边际收益，是不是已经低于
> 「把已命中的考点从 microbenchmark 升级成端到端数字」？**

如果你判断"是"，那你的方案重点应该放在**怎么把已有的东西变成简历能写的数字**；
如果你判断"不是"，请给出数据理由。

**这一条没有标准答案，我要看你的论证，不是你的结论。**
