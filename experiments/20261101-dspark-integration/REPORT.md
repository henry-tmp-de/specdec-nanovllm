# DSpark 接入与固定批量结果

## 结论

真实训练的 DSpark 已接入，CPU 和 GPU 的规定正确性检查通过；**不建议合并**。B=8 的代码、数学请求快于无投机，但一般文本慢约 20%；B=16 在统一调整内存池后，代码仅有约 1.5% 的中位数优势且三次范围重叠，数学慢约 5.7%，一般文本慢约 34%。这未达到 B8/16 相对两个基线均有超过波动净收益的要求。

原始统一显存预算 0.85 的 B16 DSpark 在 prefill OOM；未降低并发、未缩短输入或输出。随后三 arm 统一设为 0.70，重新测同样的 B16/1024/256；该组独立列出，原失败保留。调整内存池使此负载能跑通，但不能把原配置的容量失败抹掉。

## 设置与口径

- 单张现场空闲 RTX 3090，TP1，Qwen3-4B BF16 目标；对照为无投机、Qwen3-0.6B BF16 自回归 draft（k=6）、官方 DSpark Qwen3-4B block-7（**7 个候选**）。无量化、滑窗、混流、训练和动态 confidence scheduler。DSpark 的七个输入位置是 anchor + 六个 mask，七行输出预测 anchor 后的七个 token；终止附近截短候选并保留 bonus 位置。
- 原始实现来自工作区 `main` 的 `d89a7ccfc2dc0e8da0b9f15efcd54f3d098fa024`；核心接入及主矩阵代码 `7f420f4`，内存预算复测脚本 `4f8324f`。两者的推理核心相同。DSpark 权重版本 `3457dff1417cb84927f6098a5fcb7cee85c934b7`，2,786,273,970 字节，SHA-256 `f9e31587608441f235d46410e7201f8cb1647be5cd077065c89cc02c37ae86a7`；本机和服务器副本均匹配。目标模型下载元数据记载 revision `1cfa9a7208912126459214e8b04321603b3df60c`，目标 config SHA-256 `8ba006f74fecfaaeb392872a60f4a480e7ec9860153d2e1b769ec81f9a147f8a`；0.6B config SHA-256 `660db3b73d788119c04535e48cf9be5f55bc3100841a718637ae695b442f27dd`。目标和 0.6B 权重文件未整文件重新校验。
- 固定批 B=1/2/4/8/16，输入 1024、输出 256、T=1、忽略 EOS；代码 HumanEval、数学 GSM8K、一般文本 Alpaca，各 3 次，每 arm 同 prompt IDs 和 seed。任务较短时以前置 WikiText-2 自然文本补足长度：本次每条有 856–1006 个补齐 token，任务未截断，因此这主要是**带公开任务后缀的固定长度吞吐实验**，不代表对应任务的质量或真实 Agent 流量。输入及元数据见 [workload manifest](evidence/workload-manifest.json)。
- 完整请求吞吐 = 全部实际交付的输出 token / 从请求入队到全部完成的墙钟时间，包含 prefill、draft、验证、采样和调度；模型装载和图预热另计。decode 吞吐包含批次从 B 缩小至 1 的全过程；“满批 decode”只统计 active B 恰好等于目标 B 的轮。TTFT 从入队到首 token；TPOT 是每请求首 token 后耗时除以后续输出 token 数，再取请求中位数。下表均为 3 次中位数，单位 token/s。
- 目标模型沿用引擎现有 attention 路径；DSpark 使用 PyTorch SDPA 调度器和真实批量 backbone，未逐 kernel profile 判定 SDPA 实际选用的 kernel。draft 和 target verify 配置 B=1/2/4/8/16 图桶，DSpark 的图按 B 和上下文桶惰性捕获；尾批不在桶内或候选长度不齐时回退 eager。图命中、回退和捕获数均在原始记录里。

## 吞吐、尾批和成本

满批局部收益并不保证整批更快。例如 B16 数学，满 B=16 的 decode 轮 DSpark 中位约 1190 tok/s，无投机约 957；整个 decode 阶段分别约 893/957，完整请求则约 636/675。DSpark 首次重复有 38 轮满 B16，随后还出现 22 轮 B1。B8 一般文本也有类似现象：满 B8 轮约 590/560 tok/s，但完整请求为 359/450。批次收尾、不同接受长度和图回退与差距相关，现有记录不足以分别量化其因果贡献。

B16 数学中位 TTFT：无投机/AR/DSpark 为 1.805/2.278/1.869 秒；中位 TPOT 为 16.72/30.08/13.60 毫秒。B16 一般文本分别为 TTFT 1.815/2.278/1.879 秒、TPOT 16.78/53.89/23.01 毫秒。请求中位 TPOT 与最后一条请求完成所决定的整批吞吐是不同指标。

B16 一般文本，完整请求中位墙钟为无投机 6.095 秒、AR 19.850 秒、DSpark 9.249 秒；DSpark prefill 1.879 秒、decode 7.369 秒。DSpark 的 draft/verify CUDA stream 时间跨度中位约 2.352/3.896 秒，CPU postprocess 约 0.008 秒；这些事件跨度可能包含流上等待，不能直接相加作为无重叠内核账。该组 DSpark 每次提议 8881、接受前缀 2795 个候选（31.5%），平均每个活跃序列每轮实际交付约 3.18 个 token。接受数是验证阶段的前缀统计；最终吞吐只算真正交付且没有超过输出上限的 token。

B16、0.70 档三 arm 的 KV 池分别为无投机 209、AR 99、DSpark 146 个 256-token 块，所有正式 run 首个 decode 均为 B16、无抢占。DSpark 峰值 allocated 约 16.41 GiB，峰值 reserved 达约 21.71 GiB。0.85 档 DSpark 预留 234 块，首次正式 prefill 请求 304 MiB 临时量时仅剩 91.7 MiB；日志记载图私有池约 3.03 GiB。现有证据表明是内存池、图池和临时量竞争；不等于证明模型必然无法在 24 GiB 处理 B16。

## 正确性与回归证据

- CPU 契约 7/7：批量和逐条 backbone、已确认上下文、拒绝后缀、padding slot、真实前驱 Markov logits，以及 4 万样本的条件 q 与拒绝采样联合分布。原引擎 spec decode、温度广播、批量门控、多序列 prefill、prefix hash 五组 CPU 回归通过。
- 官方 checkpoint 的 64 个 tensor 均存在、形状匹配；DSpark embedding 和 lm_head 与本机 target 绑定词嵌入逐位一致。随机特征、真实 DSpark 权重的官方 GPU 参考对拍：B2、长度 31/47，hidden 相对 RMS 0.02135，14 行条件 logits 最大 KL 0.00347，14/14 top-1 一致。
- 更直接的真实链路：B2、1024 输入，从本引擎 target 抓取特征后与官方 DeepSpec 对比，14 行 top-1 全一致，两条最大 KL 为 0.00117/0.00045。B1/B2 集成 smoke 的目标验证图投影 KV 对 eager 最大差为 0；B1 用真实 p/q 的 8192 次拒绝采样，target top16+其他分桶的 TV 为 0.01396。
- 前缀复用测试命中 256 个 token，DSpark 对应 KV 位级相同，prefill target logits KL 0.00164、draft 首位 KL 0.00201。另在独立诊断进程强制接受 0/3/7 个候选，重建仅含确认特征的缓存并对拍后续条件 logits，最大 KL 小于 0.003；强制结果不作为采样分布证据。
- 原始 `main` 与接入分支的无投机默认路径，使用相同三个 1K prompt、seed 和 32 token 输出，输出哈希均一致；单次短测吞吐约 64.43–64.66 tok/s，不据此声称性能无差别。所有结果及 [原始记账审计](evidence/raw-audit-local.json) 可复算：18 个矩阵文件、153 个有效 run 和一个预期 OOM，输入哈希、真实 active B、token 交付、接受数和图命中通过。51 组重复中 50 组输出哈希完全一致；B16 代码 DSpark 首次重复有 2 次惰性图捕获、输出哈希不同，故重复的计时变化也包含这一因素。

本批累计 **1358.13 GPU 秒，约 22 分 38 秒**，包括失败和重试；没有训练。完成时 GPU7 为 15/24576 MiB、利用率 0%、无计算进程，本批无残留进程，见 [退出记录](evidence/gpu-final-state.json) 和 [预算台账](evidence/gpu_budget.jsonl)。权重不放入 Git；保留分支等待主协调审核，不自动合并或推送。
